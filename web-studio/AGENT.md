# Studio agent

Natural-language planning is performed by Amazon Bedrock Nova Pro through the authenticated OPUS AWS API. No model credentials are shipped to the browser. A prompt sends a media-free session snapshot, current selection/view/position, recent conversation, the action catalog, device ranges, and raw source peak/RMS measurements. Audio bytes stay local. Session names and MIDI notes are transmitted to AWS for model inference. Analysis is source peak/RMS, not integrated loudness, listening, or a professional mix-quality guarantee.

The agent can create and manage tracks, returns, scenes, MIDI clips and notes; edit tempo, master gain, loops, clip audio/warp/launch settings, synth/sampler/drum settings, MIDI effects, serial audio effects, sends, mixer automation, regions, time and section markers. Newly created tracks/clips/returns can use unique `$alias` references within one plan. Runtime commands support playback, pause/stop, seek, scene launch, views, project download, configurable WAV delivery and aligned all-channel stem ZIP export. Plans can stop/pause first, commit all project edits as one Undo snapshot, then run up to eight ordered transport, view and download commands. The whole plan is checked before any operation starts. Manual transport, project download and WAV export use the same runtime helpers as the agent. Project edits cannot follow a runtime navigation/playback/export command in the same plan. Browser file selection, physical audio/MIDI setup and hardware permission prompts remain user actions. Other unsupported operations are not available through the catalog and must not be claimed completed.

Each plan is applied to an isolated copy and validated by the studio's project validator before installation. Rejected plans can be repaired twice. Cancellation before execution, session replacement/edits during inference, or invalid plans leave the set unchanged. Once execution starts, cancellation or a later runtime failure stops the remaining steps and reports already-applied project edits and completed runtime operations; Undo can reverse the project edit transaction. It does not claim that prior downloads or transport operations were rolled back. Undo applies to project edits; playback/downloads are runtime operations. Export uses the real engine, not a model-generated audio file. Current mixing analysis does not perform an automatic rendered-output listening/quality review. Reference-song audio analysis is not implemented; the agent must ask for section details or explain an assumption instead of claiming it listened to a named song.

Sign in through the panel with an existing OPUS account. Existing same-origin legacy OPUS sessions can be reused. New panel sign-in is held in sessionStorage. OPUS account registration remains invitation-based. The API enforces Cognito verification and account membership before inference. DynamoDB counters limit each account to 6 model requests/minute and 100/day, including repair requests. Requests are bounded to 180 KB and responses to 6,000 tokens. Model IAM access is scoped to Nova Pro in us-east-1. No arbitrary code, shell or network tool is exposed.

Release 0.124 adds `launch_clip` (regular track ID + zero-based scene), `stop_track`, and `stop_clips`. Scene and clip commands return engine receipts; the agent waits for all requested clip quantizations and the scene boundary to pass on the audio clock before executing the next step. Gate/repeat clip holds are explicitly rejected rather than silently treated as sustained launches. No-Stop empty slots retain the previous clip. Stopping clips does not stop transport; stopping a track while paused does not start transport.

Cancellation removes only that request's unscheduled pending launches; already scheduled audio and previously active clips are not rolled back. Interrupted commands report the current engine snapshot. Stop/cancellation during clip preparation prevents a delayed launch. Engine-state observations are scheduling snapshots and can reflect lookahead; this does not prove sound on a physical device.

`export_wav` accepts `args.source` = `auto`, `session`, or `arrangement`. Auto preserves the existing preference for Arrangement when one exists. Explicit Session renders active Session clips from their beginnings for sixteen beats, even with an Arrangement present, and bypasses Arrangement mixer/device/send automation. The manual export source also supports Session WAV/stems. Arrangement MIDI export is unavailable under Session source. This is a Session clip snapshot, not capture of a mixed Arrangement/Session performance, nor preservation of live clip phase or held notes.

Evidence: `tests/agent-performance.test.cjs`, `tests/agent-session.cjs` and `tests/fixtures/agent-session-plan.json`. The generated-tone browser fixture verifies a delayed high clip, a retained no-stop pad, frequency content of Session output, unchanged muted Arrangement output, individual/all stops and cancellation without a late high-clip launch. The captured model plan can be replayed with `OPUS_AGENT_SESSION_PLAN_FIXTURE=tests/fixtures/agent-session-plan.json`. `infra/aws-backend/operator/agent-performance-model-check.mjs` performs bounded direct Bedrock planning checks without creating users or bypassing public authentication. Authenticated production inference remains unverified.


Release 0.126 adds shared delivery options to `export_wav` and `export_stems`: 44.1/48/88.2/96 kHz; 16/24-bit PCM or 32-bit float; normalization; none/triangular dither (none for float); effect tails; explicit auto/Session/Arrangement source; and zero-based Arrangement ranges. WAV can select master, `track:ID` or `return:ID`, including new-item aliases. Stems include every track and return, retain current mute/solo/crossfade, and are rendered before master gain/compression. Independent normalization/dither and the master bus mean stems are not promised to sum sample-for-sample to the master mix. Session exports remain four-bar snapshots from clip beginnings, not live phase-preserving mixed-view capture.

All options are preflighted before any plan edit; runtime and the manual export dialog use the same validator and helpers. Agent requests leave the manual dialog settings unchanged. The current WAV/stem dialog settings are inspectable in studio.delivery for requests that refer to the current export settings. Export receipts report the actual settings and effective source after rendering. A download receipt means the browser was offered the file; it does not prove the user saved it. Cancellation discards an incomplete ZIP after the current native offline channel render finishes and stops subsequent commands; already-applied project edits remain available to Undo.

Evidence: `tests/agent-delivery.test.cjs`, `tests/agent-delivery.cjs`, `tests/fixtures/agent-delivery-plan.json` and `infra/aws-backend/operator/agent-delivery-model-check.mjs`. Two operator-IAM Bedrock plans passed first attempt and were replayed through the real browser export path. Synthetic audio checks inspect headers, exact frames, aligned stems, muted/return audio, normalized float peaks and exact manual/agent sample equality, plus invalid-plan atomicity and partial-render cancellation. This is separate model planning and deterministic browser execution; authenticated public-app inference, physical output, listening quality and cross-browser download behavior remain unverified.


Release 0.127 adds `region_group` project edits with explicit Arrangement region IDs: trim, move, duplicate, delete and activation. Trim uses `edge=start|end` and a shared beat `delta`. Removing one beat from starts means `delta=+1`; removing one beat from ends means `delta=-1`. The tool schema and server prompt include these directional examples after a model check exposed the ambiguous sign. The revised contract produced both representative trim directions correctly on first attempt; captured plans are replayed in `tests/region-trim.cjs`. These are representative checks, not a guarantee of every natural-language interpretation.

Selected starts/ends move by the same quarter-beat-snapped amount, then clamp together at timeline bounds or the shortest clip's 1/16-beat minimum. Start trim keeps original ends fixed and wraps source offsets within each source loop; end trim keeps starts and offsets. Selected-to-selected or neighbor overlaps reject atomically. Source clip data/settings and track automation stay unchanged. The manual edge-drag and numeric paths use the same model operation. Starts/length/source-offset fields and Split/Consolidate continue to edit the primary clip.

After the candidate is committed and checked against the actual project, the runner reports observed requested/applied trim amounts. Clamped plans show the actual amount instead of repeating a misleading planned summary, and the readback is kept in conversational context. Each plan remains one project-history step. Full selection/focus commands, linked-track behavior, fades/crossfades and authenticated production model round trips remain open.


Release 0.127.1 distinguishes zero-change plans from applied project edits. When the validated candidate is identical, it avoids installation/history changes, reports no added Undo step and does not require stopping playback for that nonexistent edit. Real runtime commands remain separately executable. Clamped-to-zero observations remain visible and conversational.


Release 0.128 adds `export_midi` to the runtime command contract. `source: "clip"` with `clipId` exports a complete loop; `source: "arrangement"` (default) exports the whole Arrangement or a zero-based `{start,length}` range. `trackIds` chooses regular Arrangement tracks, independently of WAV channel selection. `applyEffects` defaults false; true bakes the owning track MIDI chain into notes. Clip export can infer one owner; a shared/orphaned clip requires an explicit valid owning `trackId` when applying effects. Newly created track/clip aliases and chosen-track aliases resolve before compilation. Empty and oversized exports reject during whole-plan preflight, before project edits or transport operations. Precompiled bytes are used only after stale-state and committed-candidate checks. MIDI export adds no history step; a compose-and-export plan retains one Undo step for the composition. Manual clip and Arrangement exports share the same path and settings rules, including a clip effect checkbox and chosen-track export scope. Preferences do not change project content/history, and agent commands preserve the manual settings.

Receipts measure the generated SMF format, 960 PPQN timing, end tick, note/track counts and one-based MIDI channels. Clip files use SMF 0; Arrangement files use SMF 1 with tempo, names and in-range locators shifted to the exported start. Source channels, velocity and release velocity are preserved to MIDI precision; note starts/durations round to ticks, end-crossing notes are cut at loop/region/range bounds. Inactive regions/notes and zero-velocity notes are omitted; mixer mute/solo does not filter MIDI. Instruments, audio, audio effects, automation, controller/expression data and tempo maps are outside this delivery path. Applying MIDI effects can change or remove notes. A receipt proves a browser download was offered, not saved to a user's disk. Synchronous MIDI compilation is bounded to 65,536 exported/processed notes and checks cancellation before a download, not during each native JavaScript loop.

Evidence: `tests/midi-delivery.test.cjs` (nine tests), `tests/agent-midi.cjs`, `tests/fixtures/midi-delivery-project.mjs`, and `infra/aws-backend/operator/agent-midi-model-check.mjs`. Two Nova Pro operator-IAM requests passed first attempt and their captured action plans (`tests/fixtures/agent-midi-plan.json`) replay through the browser with `OPUS_AGENT_MIDI_PLAN_FIXTURE=tests/fixtures/agent-midi-plan.json`. The browser checks actual downloaded headers, exact manual/agent file equality, no export history/project mutation, invalid late export atomicity, aliased composition with one Undo, and import/reexport in a fresh 390px mobile context with tempo, channels, timing and velocities checked. This separates real-model planning from intercepted API replay; authenticated production inference remains unverified.

A 300-beat Arrangement export is verified without truncation; the existing importer still rejects beyond 256 beats. Import remains limited to 2 MB, 16 groups/tracks and 4,096 notes per group, so exported long/dense files are not promised to reimport. Full-song interchange fidelity, expressive MIDI/controller support, cross-browser behavior, physical output and listening-quality assessment remain open.


## Release 0.129 — Arrangement Audio Fades

Audio and generated-loop Arrangement regions now have independent, non-destructive linear fades. Pointer handles and a vector envelope appear in the timeline; Clip detail exposes Fade In/Out Beats, Reset Fades and explicit application to selected clips. Fade duration accepts fractional beats (4 ms at 120 BPM is 0.008 beats). Dragging is continuous to 0.001 beat precision; Shift uses a 1/16-beat grid. Numeric fields support finer precision. Dragging clamps at the opposite fade/source-loop boundary; numeric and agent requests reject invalid durations atomically. A canceled drag changes neither project nor history. Source clips and Session playback are unchanged.

The new `region_fades` project action accepts Arrangement region `ids`, `fadeIn` and/or `fadeOut` in beats; zero removes an edge. MIDI selections, unknown IDs/fields, overlap and crossing a source-loop boundary reject the entire plan before any earlier edit. Applying to a group is one Undo step. The model receives explicit region-ID and millisecond conversion examples; both one-beat/quarter-beat and 4 ms requests passed first-attempt operator-IAM checks. Captured actions replay in the browser (`OPUS_AGENT_FADES_PLAN_FIXTURE=tests/fixtures/agent-fades-plan.json`), with observed duration readbacks. This separates real planning from intercepted API browser execution; signed-in production inference remains unverified.

Fade gain is scheduled before track effects on the Arrangement region clock, independently of repeating source phase and mixer automation. Contiguous scheduler windows retain source nodes and resampling phase; seeks start at the current fade level, and later loop passes restart the region envelope. Full/ranged WAV and stems share this scheduler. Ranged exports retain the original fade end instead of moving it to the export boundary. Splits, time insert/delete/duplicate and time clipboard slices retain the original linear ramp levels. Replacing a duration sets that edge to a full fade. Trimming retains the cropped segment; extending an edge carries that edge fade to the new boundary, fitting it to available source-loop/region space. Consolidation bakes fades and clears region ramps so they are not applied twice. Clipboard/duplicate region fade data is independent. Changing the Split At field no longer creates a spurious refresh/history event that can swallow its following Split click.

Evidence: seven `tests/region-fades.test.cjs` cases; `tests/region-fades.cjs` for numeric, pointer, group, Escape, limits, split, captured model plans, invalid-plan atomicity, single Undo, mobile millisecond editing/menu Undo, and saved-project reopening; `tests/region-fades-audio.cjs` for float WAV samples and the shared live-window scheduler. At 44.1 kHz, the measured envelope differs from independently calculated linear gain by less than 1.6e-8. A ranged export is sample-identical to the corresponding full-render segment; split preservation differs by less than 1.5e-8; unselected and Session audio are sample-identical. Consolidation differs by about 1.1e-7; the corresponding delay-tail render differs by less than 6.5e-8 and retains nonzero tail energy. Whole versus 0.3-beat scheduling windows and repeated loop passes are identical in the fixture; an interior seek differs by less than 1.5e-8. These are synthetic Chromium render checks, not physical-output, listening-quality or cross-browser proof.

Reference: [Live 12 audio clip fades and crossfades](https://www.ableton.com/en/live-manual/12/arrangement-view/#audio-clip-fades-and-crossfades) describes edge fades, curve handles, loop/overlap limits and adjacent crossfades. This release implements linear edge fades and the loop/overlap limits. Curve/peak handles, adjacent crossfades, automatic click-prevention fades and exact native linked-track/trim behavior remain unimplemented or unverified. Full Ableton feature/workflow parity and natural-language control across the application remain active requirements.

# Studio agent

Natural-language planning is performed by Amazon Bedrock Nova Pro through the authenticated OPUS AWS API. No model credentials are shipped to the browser. A prompt sends a media-free session snapshot, current selection/view/position, recent conversation, the action catalog, device ranges, and raw source peak/RMS measurements. Audio bytes stay local. Session names and MIDI notes are transmitted to AWS for model inference. Analysis is source peak/RMS, not integrated loudness, listening, or a professional mix-quality guarantee.

The agent can create and manage tracks, returns, scenes, MIDI clips and notes; edit tempo, master gain, loops, clip audio/warp/launch settings, synth/sampler/drum settings, MIDI effects, serial audio effects, sends, mixer automation, regions, time and section markers. Newly created tracks/clips/returns can use unique `$alias` references within one plan. Runtime commands support playback, pause/stop, seek, scene launch, views, project download, configurable WAV delivery and aligned all-channel stem ZIP export. Plans can stop/pause first, commit all project edits as one Undo snapshot, then run up to eight ordered transport, view and download commands. The whole plan is checked before any operation starts. Manual transport, project download and WAV export use the same runtime helpers as the agent. Project edits cannot follow a runtime navigation/playback/export command in the same plan. Browser file selection, physical audio/MIDI setup and hardware permission prompts remain user actions. Other unsupported operations are not available through the catalog and must not be claimed completed.

Each plan is applied to an isolated copy and validated by the studio's project validator before installation. Rejected plans can be repaired twice. Cancellation before execution, session replacement/edits during inference, or invalid plans leave the set unchanged. Once execution starts, cancellation or a later runtime failure stops the remaining steps and reports already-applied project edits and completed runtime operations; Undo can reverse the project edit transaction. It does not claim that prior downloads or transport operations were rolled back. Undo applies to project edits; playback/downloads are runtime operations. Export uses the real engine, not a model-generated audio file. Current mixing analysis does not perform an automatic rendered-output listening/quality review. Reference-song audio analysis is not implemented; the agent must ask for section details or explain an assumption instead of claiming it listened to a named song.

Sign in through the panel with an existing OPUS account. Existing same-origin legacy OPUS sessions can be reused. New panel sign-in is held in sessionStorage. OPUS account registration remains invitation-based. The API enforces Cognito verification and account membership before inference. DynamoDB counters limit each account to 6 model requests/minute and 100/day, including repair requests. Requests are bounded to 180 KB and responses to 6,000 tokens. Model IAM access is scoped to Nova Pro in us-east-1. No arbitrary code, shell or network tool is exposed.

## Release 0.129 — Arrangement Audio Fades

Audio and generated-loop Arrangement regions now have independent, non-destructive linear fades. Pointer handles and a vector envelope appear in the timeline; Clip detail exposes Fade In/Out Beats, Reset Fades and explicit application to selected clips. Fade duration accepts fractional beats (4 ms at 120 BPM is 0.008 beats). Dragging is continuous to 0.001 beat precision; Shift uses a 1/16-beat grid. Numeric fields support finer precision. Dragging clamps at the opposite fade/source-loop boundary; numeric and agent requests reject invalid durations atomically. A canceled drag changes neither project nor history. Source clips and Session playback are unchanged.

The new `region_fades` project action accepts Arrangement region `ids`, `fadeIn` and/or `fadeOut` in beats; zero removes an edge. MIDI selections, unknown IDs/fields, overlap and crossing a source-loop boundary reject the entire plan before any earlier edit. Applying to a group is one Undo step. The model receives explicit region-ID and millisecond conversion examples; both one-beat/quarter-beat and 4 ms requests passed first-attempt operator-IAM checks. Captured actions replay in the browser (`OPUS_AGENT_FADES_PLAN_FIXTURE=tests/fixtures/agent-fades-plan.json`), with observed duration readbacks. This separates real planning from intercepted API browser execution; signed-in production inference remains unverified.

Fade gain is scheduled before track effects on the Arrangement region clock, independently of repeating source phase and mixer automation. Contiguous scheduler windows retain source nodes and resampling phase; seeks start at the current fade level, and later loop passes restart the region envelope. Full/ranged WAV and stems share this scheduler. Ranged exports retain the original fade end instead of moving it to the export boundary. Splits, time insert/delete/duplicate and time clipboard slices retain the original linear ramp levels. Replacing a duration sets that edge to a full fade. Trimming retains the cropped segment; extending an edge carries that edge fade to the new boundary, fitting it to available source-loop/region space. Consolidation bakes fades and clears region ramps so they are not applied twice. Clipboard/duplicate region fade data is independent. Changing the Split At field no longer creates a spurious refresh/history event that can swallow its following Split click.

Evidence: seven `tests/region-fades.test.cjs` cases; `tests/region-fades.cjs` for numeric, pointer, group, Escape, limits, split, captured model plans, invalid-plan atomicity, single Undo, mobile millisecond editing/menu Undo, and saved-project reopening; `tests/region-fades-audio.cjs` for float WAV samples and the shared live-window scheduler. At 44.1 kHz, the measured envelope differs from independently calculated linear gain by less than 1.6e-8. A ranged export is sample-identical to the corresponding full-render segment; split preservation differs by less than 1.5e-8; unselected and Session audio are sample-identical. Consolidation differs by about 1.1e-7; the corresponding delay-tail render differs by less than 6.5e-8 and retains nonzero tail energy. Whole versus 0.3-beat scheduling windows and repeated loop passes are identical in the fixture; an interior seek differs by less than 1.5e-8. These are synthetic Chromium render checks, not physical-output, listening-quality or cross-browser proof.

Reference: [Live 12 audio clip fades and crossfades](https://www.ableton.com/en/live-manual/12/arrangement-view/#audio-clip-fades-and-crossfades) describes edge fades, curve handles, loop/overlap limits and adjacent crossfades. This release implements linear edge fades and the loop/overlap limits. Curve/peak handles, adjacent crossfades, automatic click-prevention fades and exact native linked-track/trim behavior remain unimplemented or unverified. Full Ableton feature/workflow parity and natural-language control across the application remain active requirements.


## Release 0.130 — Adjacent Audio Crossfades

Two selected, ordered audio/generated-loop regions on one track can now form a linear crossfade. Crossfade Pair exposes overlap start/length and Create/Resize/Remove controls. A monochrome vector join selects both sides, and Create-menu commands use the displayed pair settings. The Studio Agent uses `region_crossfade` with `leftId`/`rightId` (Arrangement region IDs), `action: create`, zero-based `start` and positive `length`; remove accepts an optional `boundary` inside the overlap, defaulting to its midpoint. Creation/resize keeps the outgoing start and incoming end, moves the two inside edges, and updates incoming source offset to preserve timeline phase. Source clips, track settings and automation remain unchanged. One Undo restores both regions. Removal joins the edges at the chosen boundary and clears only their paired fades.

The overlap must cover their existing join and fit available source time inside each loop. For example, regions meeting at beat 4 use start 3.5/length 1 for a centered one-beat overlap, if both source handles permit it. Missing source handles reject rather than silently wrapping or moving song sections. Normal overlaps and MIDI overlaps remain invalid. Project validation admits an audio overlap only when opposing linear gain factors sum to one throughout it, checking all ramp boundaries. Third/unrelated overlaps and broken pair fades reject atomically. Use Crossfade Pair controls to alter the join; independent fade edits cannot break its complement. A default suggested range can bias toward the side with available source material; explicit agent/manual ranges are never silently substituted. The loop grid is logical source timing; arbitrary imported metadata is not proof of non-silent waveform content.

The live scheduler now carries each Arrangement slice's region identity and uses that source's own fade, offset and end limit. Both overlapping sources feed the same track processing. Offline WAV/range/stems already schedule every region and use the same gain path. Group moves, time slicing, split and clipboard operations preserve valid complementary ramps. Consolidating either side includes every connected overlap region on that track, renders their combined active audio before track effects, and replaces the passage with one independently editable audio clip. Inactive sources remain silent in the bake, unrelated tracks are unchanged, original source clips remain stored, and all region/media inputs are checked for changes before installation. This avoids either dropping the partner or applying baked fades twice. The existing 0.25–256 beat / 30 MB mono/stereo consolidation limits apply to the whole passage.

## Release 0.131 — Studio Agent Session Renewal

A normal Chrome check on release 0.130 reached the real agent endpoint but returned “Sign in again” for the existing cached session. The published agent forwarded its access token without using the backend's already-supported refresh grant. Release 0.131 adds one account-bound browser transport for sign-in, renewal, every planning/repair request and sign-out. It renews within 60 seconds of a known expiry, or refreshes and retries one bare/model 401 once. A second 401 ends that local sign-in; malformed or temporary service failures preserve credentials for retry. Concurrent requests share one renewal in the current page. The refreshed session is saved to the same private/shared source, with an in-memory fallback if writes fail. No backend runtime or account creation changes are required.

Each request binds its source, session version and immutable user ID. Sign-out, external account changes and same-user reauthentication invalidate old requests; a late refresh cannot overwrite a newer account or restore a logged-out session. Identity is checked after analysis and planning, before applying edits, and through the execution runner. Account changes clear conversational context and reset login fields; the post-analysis check prevents a finishing analysis from reintroducing the previous user's prompt. Passwords are cleared after successful or failed login attempts. Tokens are not included in planning bodies, public account snapshots, conversation output or observations. Auth requests do not forward old bearer tokens, redirects are rejected, and timeout/cancel checks bound network use. Browser-token availability is displayed as account state, rather than proof of a current server-authenticated session.

Canceling while renewal is pending stops that request before model planning. A shared renewal can finish for future use, unless the identity/session changed. Transient failures and quotas do not silently log the user out. Expired/rejected refresh credentials open the existing sign-in form without changing the project. Sign-out clears the active local source immediately and best-effort revokes that session through the existing logout endpoint; if remote confirmation fails, the UI only claims sign-out in this studio. This does not prove global/other-device revocation.

Evidence: `tests/agent-session-auth.test.cjs` (12 cases), `tests/agent-session-auth.cjs`, and the added server refresh/identity case in `infra/aws-backend/tests/contracts.test.mjs`. Browser cases cover inherited expired shared sessions, bare-401 renewal/retry, account display, one Undo, logout during a model request, failed renewal, account switching during planning and analysis, cancellation during refresh, and failed/successful sign-in with password clearing. Existing `tests/studio-agent.cjs` and `tests/agent-layout.cjs` still pass. These are controlled auth/model responses. After publication, normal Chrome successfully performed a real signed-in session read, a tempo change from 120 to 123 BPM and Edit-menu Undo back to 120; the composition-to-WAV proof below uses the same renewed-session path. No production authentication bypass or synthetic user is used. Wider browser/storage/offline and MFA/role/revocation cases remain unverified, as do the remaining full Ableton and application-wide agent workflows.

## Release 0.132 — Agent Selection and Detail Navigation

The Studio Agent can now bring the part of the project it is working on into view. Runtime `select` supports track/return devices, a Session clip on a regular track, and one or more Arrangement regions with an explicit primary. Runtime `show_panel` opens Clip, Devices, Recording or Returns detail. These operations change view state only: they do not launch clips, seek, start recording, connect hardware, edit music or add Undo steps. Existing manual Session-clip clicks, Arrangement selection clicks and device-target changes use the same validated selection helpers. Every agent step reports observed selection/view/panel state and names in Selection Details, which also enters conversational context. Context distinguishes the selected clip from the separate device-track target.

`select` examples: `{target:"track",trackId:"room"}` opens that track/return’s devices while preserving the current clip content selection; `{target:"clip",trackId:"bass",scene:1}` selects displayed scene 2 without launching it; `{target:"regions",ids:["region-a","region-b"],primaryId:"region-b"}` selects both regions and opens the primary clip. Scene indices are zero-based. Selecting by clipId requires a unique slot on its owning track; shared clips in multiple slots require scene. The selected Arrangement range is revealed, fitting the viewport when necessary. Clip/region selection opens Clip detail; track selection opens Devices. `show_panel` can then intentionally choose another detail panel.

New region creation accepts a unique `ref` alias, resolved in later selection ids/primaryId along with existing track and clip aliases. A ref on an existing/deleted region, mixed clip/region IDs, repeated/stale region IDs, mismatched Session ownership and unsupported selection/panel fields reject the whole plan before edits or runtime actions. Selecting a missing slot reports its zero-based index and occupied indices. Selection and panel changes are guarded during active note, velocity, audio-fade, region, time, automation and marquee drags or busy/input operations. Project edits still precede navigation and share one Undo; navigation cannot consume that history step.

Opening a MIDI clip now fits all its pitches using the existing pitch-fit calculation. The prior first-note-centered octave hid pitch 43 in the four-note bass proof; all four notes now appear without manually enabling Fold. This is a view fix and does not transpose or edit notes.

Its actual downloaded project showed both MIDI clips still named Agent MIDI, despite the model summary claiming Navigation A and Navigation B. One Undo restored the byte-identical original project before further testing. The result was treated as an incomplete requested workflow, not accepted from its summary.

The model system, shared schema and action catalog now distinguish a clip’s display name (`midi.args.name`) from its internal `ref` alias. The composition example supplies a MIDI display name; instructions require preserving explicitly requested names and forbid claiming a name that was not supplied. A fifth operator canary matches the larger real request and verifies both names, four notes per clip, displayed scenes 1/2 as internal indices 0/1, return/track preservation, region positions and final group primary/panel. The verifier checks the final navigation outcome, allowing harmless repeated selection steps rather than rejecting a valid plan solely for its command count. It retains controlled failures and uses bounded backoff when no plan is available.

Current model evidence (`tests/fixtures/agent-selection-plan.json`): clip, offscreen regions, return panel and the named two-clip group passed first attempt. The separate single-clip composition needed one explicit semantic repair from scene index 1 to 0. That operator-provided semantic correction is distinct from the app’s contract validation; it does not prove the production app detects every user-intent mismatch automatically. Seven selection unit cases, all 115 core and 18 backend checks and artifact/module validation passed. The new captured-plan regression verifies the named multi-clip result and final primary against actual project data. Final signed-in publication checks follow deployment; broader semantic outcome review and the full DAW/application-wide agent objective remain open.
